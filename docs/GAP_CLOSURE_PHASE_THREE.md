# Gap closure — Phase 3: recovery and scale

## Implemented

- **G10: validated media.** Stream uploads with a 20 MB original / 8 MB derivative limit. Decode PNG with CRC checking and JPEG with strict decoding and a 96 MB decoder memory ceiling. Read actual dimensions, with a 24-million-pixel / 16,384-pixel side limit. Reject MIME mismatches, truncated/signature-only files and arbitrary derivative bytes. Originals now have a PNG/JPEG contract; the app converts other selected formats (including HEIC) to JPEG. Analysis/thumbnail derivatives must be JPEG. Converted formats represent a still image, not preserved animation. Direct API callers must normalize other formats first.
- **G11: repairable media storage.** Reuploading a matching hash writes validated bytes back to its existing R2 key, repairing absent or corrupt originals. New uploads use a deterministic client-and-hash identity so concurrent requests cannot create duplicate assets. Persist the D1 identity before writing R2: a database rejection creates no orphan object; an R2 failure leaves a durable, repairable identity. Derivatives use one stable key per asset/kind, bounding objects when a derivative database write fails. A lost response can be retried with the same image.
- **G12: explicit API origins.** Removed `Constants.isDevice`. A pure origin resolver uses build metadata, platform, configured origin and development mode. Installed apps default to the hosted API, explicit development LAN URLs work, release origins reject loopback/HTTP, staging requires its isolated HTTPS origin, and fixture builds permit only their isolated loopback API. Build metadata is embedded by app.config.js and travels with JavaScript updates. Web can use its own origin. Staging OTA/build commands must continue supplying their staging environment configuration.
- **G13: legacy creation retirement.** POST `/v1/generation-jobs` returns HTTP 410 with `/v1/creation-jobs` as its replacement. It creates no work. Update older clients; the supported endpoint requires readiness, destinations, ownership and an idempotency key. Existing generation lookup/retry/cancel routes remain supported. Queue/interleaving regressions now exercise the supported creation endpoint.
- **G14: complete paused recovery.** Authorized cursor pagination, stable creation-date/ID ordering, validated search/cursors and UI search/load-more controls expose work after the first 100 rows. Recovery mutations retain existing authorization and state guards.
- **Durable analytics.** Manual sync returns HTTP 202 after persisting an account job and a snapshot of post IDs. Concurrent requests for the same account coalesce. A queue delivery processes one post; claims and conditional writes fence duplicate/expired workers. Progress and partial errors remain stored and visible after leaving/reopening Analytics; the screen polls while work is active. Queue-send failures remain recoverable by cron. Provider failures retain previous metrics. Unsupported LinkedIn member analytics remains explicit. Bulk manual requests admit at most 20 accounts; larger workspaces are directed to select a client and sync its accounts. Manual sync uses the selected 1–365-day range, with at most 1,000 posts per account/range; an oversized range tells the user to shorten it. Cron defaults to 90 days and selects up to 20 eligible accounts by least recent job attempt, excluding active jobs so failed/unsupported accounts cannot permanently occupy the first batch. At most 20 recoverable jobs are redispatched per maintenance tick. Retries of terminal partial jobs create a fresh explicit sync.
- **Generation reconciliation.** Refresh replaces current server membership across the number of pages already loaded. Jobs leaving a status/search filter disappear; older loaded matching pages remain available. Explicit job deep links remain pinned.
- **Dashboard day policy.** “Publishing today” uses and labels the workspace timezone. The API returns the timezone and actual start/end instants; DST days need not contain 24 hours.
- **Input and resource contracts.** Common JSON validation bounds bodies to 256 KB, requires an object and validates shared text fields before route code uses them. Signed webhook bodies bypass this normalization so signature verification uses exact bytes. A common JSON error boundary protects callers from uncaught failures without exposing internal errors. Database triggers enforce 10 active / 50 daily creation jobs per client, 2,000 media identities per client and 100 active analytics jobs across the workspace. These are source-defined capacity limits; the owner must review media capacity when reached. Existing per-request creation asset/output limits remain enforced. Provider response buffering is capped at 32 MB. Maintenance deletes bounded batches of terminal analytics jobs older than 30 days, run history older than 90 days and superseded old metric samples, retaining current measurements.
- **Branding acceptance.** Both review surfaces explicitly require inspection of the graphic, logos and lettering. Readiness exposes the same notice. AI layout instructions do not guarantee exact logo reproduction; this phase does not add deterministic image compositing. Human visual approval remains required before publication.

## Migration and rollout

Apply **0028_recovery_jobs.sql**, after Phase 1's **0027_gap_closure_integrity.sql**, before deploying this Worker. It adds analytics jobs/items, an active-job uniqueness constraint and capacity triggers. The schema manifest includes the new tables, indexes and trigger definitions. Existing generation queue bindings carry analytics messages; no additional Cloudflare queue is needed. Deploy the Worker and matching app JavaScript together through staging. No production migration, deployment, OTA or pilot activation was performed here.

The JPEG decoder is a JavaScript dependency (`jpeg-js` 0.4.4), with explicit decoding limits; there is no new native module. A native rebuild is not required solely for that dependency. Physical conversion/permissions and staging app identity still require device acceptance.

## Verification and remaining release gates

Phase 3 regression coverage verifies actual byte validation, dimensions, missing/corrupt-object repair, concurrent uploads, D1/R2 failure recovery, streaming cancellation, legacy retirement, authorized recovery past 100 rows, build-origin variants, analytics coalescing/queue recovery/claims/progress, JSON/webhook handling, generation refresh, resource admission and DST boundaries. Prior tests retain their behavior assertions; obsolete upload fixtures now use correctly encoded PNG files.

264 Node tests passed, including 20 Phase 3 regressions. Root and Worker TypeScript, lint, formatting, schema and launch checks passed; web export and Worker packaging dry run passed. Playwright discovered 171 cases; a targeted browser attempt failed at launch because the executable is absent. Browser executables are unavailable in this environment, so test discovery is not browser acceptance. The dependency gate still rejects the previously identified deepmerge advisory; no exception or incompatible toolchain override was added. Dependency disposition, complete browser/device/provider acceptance, hosted green CI, isolated restoration and controlled pilot evidence remain Phase 4 release gates.
